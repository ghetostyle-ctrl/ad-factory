# HyperFrames 라벨·자막·음성 편집

새 카피 먼저 대본의 설명 장면은 글자 없는 CLEAN/INFO와 Veo 3.1 Lite 원본을 쓴다. `labelLayer`에 저장한 문구·앵커 계획을 앱이 HyperFrames로 합성하고 기존 최종 조립에 연결한다. 카피·대본·이미지 확인 및 유료 생성 승인 절차는 그대로 유지한다.

## 설치

- Bun 1.3.14 이상, Node.js 22 이상, FFmpeg/FFprobe와 한글 글꼴이 필요하다.
- `bun install --frozen-lockfile`로 고정된 HyperFrames 0.8.143·GSAP 3.14.2를 설치한다. 렌더는 로컬 실행이며 생성 API를 호출하지 않는다. 최초 Chromium 실행 준비는 HyperFrames 설치 환경에 따라 다운로드가 필요할 수 있다.
- 주 라벨 글꼴은 번들 Pretendard Bold다. 글꼴·Node·렌더러가 없거나 배치가 불가능하면 제작을 중단하고 원인을 표시한다.

## 공통 편집 값

공용 값은 `shared/ad-edit-style.ts`, 생성 지침은 `instructions/flow.md`의 `HF_LABEL_LAYER_RULES`다.

- 03 배지: 진올리브 #3E4A22·흰 글자·완전한 둥근 모서리·그림자 한 겹. 기본 68px, 64~72px, 자간 −2%, 왼쪽 정렬, 고정폭 숫자.
- 한 줄 높이 2em, 좌우 .8em, 최대 폭 80%. 16자 초과만 어절 줄바꿈을 허용한다. 문구를 자르거나 작은 글씨로 숨기지 않는다. 긴 문구와 동시 배치가 맞지 않으면 계획 수정이 필요하다.
- 골드 앵커 반지름13px·흰 테두리4px. 주 연결선은 수직→짧은 수평 두 마디, 올리브5px 바깥 흰 테두리2px. 수평 도달 범위는 화면15% 이내다.
- 배지 .4초 성장·완성 문구 전체 페이드. 글자 와이프 없음. 꼭 필요한 보조 정보만 `role: supporting`으로 02 기술 콜아웃 48px을 쓴다.
- 자막은 실사 y1228·설명 y1464에 배치한다(1080×1920 기준). 영상 기획의 의미에 따라 기본 고딕·손글씨·굵은 제목체·둥근체·바탕체를 선택하고 핵심어에만 색/크기 차이를 준다. 설명 장면은 기본 서체·아이콘 없음으로 03 라벨을 보존한다. 실제 글꼴·크기·연출과 적용 경계는 [상황별 광고 자막](AD-CAPTION-STYLES.md)을 따른다.
- 실제 음성의 앞뒤 조용한 구간만 측정한다. 문장 내부 호흡과 원문·원본 WAV는 보존한다. 보존한 발화 앞뒤 여유를 포함해 일반적인 들리는 문장 간격 .2~.35초를 목표로 하고, 라벨/컷의 최소 읽기 시간이 필요하면 더 길 수 있다. 긴 잔여 공백은 경고로 남긴다.

## 합성 경로와 보존

`RenderProduction` → `renderHfClip` → 원본 전체에 라벨 합성 → 원본 시각별 세그먼트 선택 → 음성 믹스·구절 자막 → 최종 MP4.

- 원본·계획·글꼴·스타일·해상도 해시로 합성 결과를 캐시한다. 부분 실패는 완성 캐시로 처리하지 않는다. 원본 오디오는 제거한다.
- 라벨 좌표를 보존하도록 설명 컷의 추가 크롭·카메라 효과를 적용하지 않고 보고서에 기록한다. 실제 원본에서 글자/물체 변형이 발견돼도 라벨로 가려 통과시키지 않는다.
- 원본8초 시각과 컷의 offset을 함께 검사한다. 모든 라벨의 완성 문구가 선택 구간에서 최소1초 읽히지 않으면 조립을 중단한다.
- 카피 먼저 방식은 실제 발화·읽기에 맞춰 시간을 줄인다. 계획 길이를 채우기 위한 무음이나 30초 강제 패딩을 추가하지 않는다. 저장된 완성 영상은 자동으로 다시 만들지 않는다.
- **자동 합성은 구현됐지만 자동 대상 추적은 아니다.** 앵커는 계획 좌표다. 최종 영상에서 대상 위치, 물체 가림, 연결선, 모바일 가독성을 사람이 확인해야 한다. 새 유료 생성 결과에 대한 품질 보증을 뜻하지 않는다.
