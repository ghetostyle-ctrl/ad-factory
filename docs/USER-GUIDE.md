# AD FACTORY 설치·사용 설명서

대상: 소스를 다운로드해 자신의 컴퓨터에서 광고 소재를 만들려는 사용자.
버전: 최초 공개 개발용 베타. 이 문서는 소스 ZIP과 별도로 다운로드해 보관할 수 있습니다.

## 1. 설치 준비

Windows 기준으로 안내합니다. Bun 1.3.14에서 검증했습니다. 설치 프로그램은 공식 배포처를 이용하세요.

- Bun: Windows 실행기가 없을 때 자동 설치합니다. 수동 설치 안내: https://bun.sh/docs/installation
- FFmpeg: https://ffmpeg.org/download.html
- 소스: https://github.com/ghetostyle-ctrl/ad-factory

영상 분석·업로드·결과 확인에는 FFmpeg에 포함된 ffmpeg와 ffprobe가 필요합니다. PATH에 등록한 뒤 새 터미널에서 다음 명령이 실행되는지 확인합니다.

```sh
bun --version
ffmpeg -version
ffprobe -version
```

## 2. 다운로드와 실행

GitHub Releases의 소스 ZIP 또는 Code → Download ZIP을 내려받아 쓰기 가능한 폴더에 압축을 풉니다. ZIP 안에서 바로 실행하지 마세요.

Windows에서는 `start-local.cmd`를 더블클릭합니다. Bun이 없으면 공식 설치 스크립트로 Bun 1.3.14를 앱의 `.runtime/bun` 폴더에 자동 설치합니다. 관리자 권한과 시스템 PATH 변경은 필요하지 않습니다. 이미 PATH에 등록된 Bun은 그대로 사용합니다. 이어서 첫 실행에 의존성을 설치한 뒤 화면을 빌드하고 로컬 서버를 시작합니다. 브라우저가 열리지 않으면 `http://127.0.0.1:4317/`에 접속합니다.

첫 실행에는 인터넷 연결이 필요하며 다운로드·빌드에 몇 분 걸릴 수 있습니다. 실패하면 창에 표시된 오류를 확인하고 다시 더블클릭하세요. 자동 설치한 Bun은 앱 안에 있으므로 터미널 수동 명령을 쓸 때는 `bun` 대신 `.runtime/bun/bin/bun.exe`를 사용하거나 Bun을 별도로 설치합니다. FFmpeg/ffprobe는 이 실행기가 자동 설치하지 않습니다.

수동 실행:

```sh
bun install --frozen-lockfile
bun run build
bun run start
```

macOS/Linux에서는 수동 명령을 사용할 수 있으나 이번 배포의 실제 검증 환경은 Windows입니다. 별도의 EXE나 Bun 내장 패키지는 제공하지 않습니다.

## 3. API 키 연결

왼쪽 아래 **연결 설정**을 엽니다. 필요한 공급자의 본인 키를 입력하고 저장합니다. 화면에 ‘세션에 저장’이라고 표시되더라도 현재 구현은 설치 폴더의 `.env`에 영구 저장합니다.

| 연결 | 사용 용도 | 키 발급 화면 |
|---|---|---|
| OpenAI | 텍스트 기획, 이미지 제작·검토 | https://platform.openai.com/api-keys |
| Gemini | Veo 영상 클립(Flow 수동 모드에서는 불필요) | https://aistudio.google.com/app/api-keys |
| Typecast | 내레이션 음성 합성 | https://typecast.ai/ |
| Meta | 기존 광고 집행 코드용 선택 설정 | 소재 제작만 할 때 필수 아님 |

Typecast 키를 연결하면 영상 대본의 문장별 내레이션을 합성해 완성 영상에 넣습니다. 합성은 유료 호출이므로 기본 설정에서는 대본을 승인한 뒤에 시작합니다.

‘설정 감지’는 키 존재 여부입니다. 인증·모델 접근 권한·사용 한도·결제 상태를 모두 확인했다는 뜻은 아닙니다. 키 입력란은 저장 후 비워질 수 있습니다. 목록의 설정 감지 여부를 확인하세요.

직접 설정하려면 `.env.example`을 `.env`로 복사하고 값을 입력한 뒤 서버를 다시 시작합니다. 실제 키는 GitHub, 이슈, 스크린샷에 넣지 마세요. 키는 암호화 저장되지 않습니다.

## 4. 프로젝트와 자료 등록

1. **자료 라이브러리 → 새 프로젝트**를 선택합니다.
2. 제품명, 브랜드, 제품 정보와 참고 광고 자료를 등록합니다.
3. 출처 URL을 입력하면 읽을 수 있는 페이지의 제목·본문을 초안으로 가져옵니다. 쇼핑몰이 접근을 막거나 이미지로만 상세 정보를 제공하면 직접 내용을 입력하거나 지원되는 이미지 첨부·읽기 기능을 사용합니다.
4. 자동으로 읽은 내용은 저장 전에 확인합니다.
5. Success AI 자료는 별도 실행 중인 Success AI 또는 JSON 가져오기를 사용합니다. 앱 선택 메뉴의 다른 로컬 주소는 해당 앱을 따로 설치·실행해야 열립니다.

자료를 등록한 뒤 **이 프로젝트로 작업 만들기**를 누릅니다. 작업 생성 시 자료 버전이 고정됩니다. 이후 라이브러리 수정 내용은 기존 작업에 자동 반영되지 않으므로 새 자료를 쓰려면 새 작업을 만드세요.

## 5. 이미지와 영상 수량 설정

소재 자동 제작 설정에서 이미지 1~10개, 영상 0~10개를 선택합니다. 먼저 이미지 1개·영상 0개로 연결과 결과를 확인하면 흐름을 익히기 쉽습니다. 공급자 호출에는 API 요금이 발생할 수 있습니다.

전략·기획을 생성하고, 영상이 있으면 대본·컷별 화면·텍스트·필요 이미지와 클립·Flow 제작 지시·편집 지시를 저장합니다. 대본을 직접 확인·수정해 승인하면 대표 이미지·카드·내레이션·AI 정지 이미지·Veo 시작 이미지와 클립·모션그래픽을 만들고 자막·BGM을 넣어 완성 영상(`video-final-<n>.mp4`)으로 조립합니다. Veo 클립은 Veo API 또는 Google Flow 웹(Google AI Pro 구독)에서 직접 만들어 올리는 방식 중 고를 수 있습니다.

**고객 질문 설계 (메타 안드로메다 대응).** 기획 단계는 광고안을 만들기 전에 고객이 구매 전에 품는 질문을 1~12개 먼저 정합니다. 질문마다 종류(구매 이유·망설임·판단 기준), 근거(실제 고객 목소리·제품 사실·추정), 답하려면 보여 줘야 할 증거를 적습니다. 각 광고 가설은 어느 질문에 답하는지, 구매 흐름의 어느 단계(필요 인식·비교·최종 결정)를 맡는지, 어떤 증거를 보여 주는지 함께 기록합니다. 광고안끼리 같은 질문만 반복하지 않고 서로 다른 고객 상황을 다루게 하려는 설계이며, 결과는 작업 공간의 기획 근거 화면에서 확인할 수 있습니다.

**인식 단계와 4가지 신호.** 광고안마다 고객 인식 단계(TOFU: 제품을 모름 · MOFU: 비교 중 · BOFU: 결정 직전)와 네 가지 신호를 정합니다. ① 부르는 대상(넓은 범주가 아니라 상황까지 특정한 사람), ② 페인포인트(이미 시도했지만 실패한 경험 등 구체적인 불편), ③ 메커니즘(우리만의 작동 방식, "X가 아니라 Y 때문" 같은 원인 재해석, 또는 실제 고객 후기), ④ 오퍼(BOFU에서만, 자료 라이브러리에 등록한 **오퍼** 자료를 근거로). 광고안이 3개 이상이면 세 단계를 모두 넣고, 5개 이상이면 문제 제기형·메커니즘 설명형 카드뉴스·사용자 리뷰·혜택 강조형·리스크 제거 강조 소재를 자료가 허락하는 만큼 편성합니다. 할인·체험·환불 보장 같은 오퍼를 광고에 쓰려면 **오퍼 자료**를, 리뷰 소재를 쓰려면 **고객 후기** 자료를 먼저 등록하세요. 등록되지 않은 오퍼는 지어내지 않습니다.

**형식별 제작물.** 메커니즘 설명형 소재는 **카드뉴스**(표지 포함 3~5장)로 만듭니다. 표지가 검토를 통과하면 나머지 카드를 장마다 만들고 검토하며, 결과물 메뉴와 기획 근거 화면에서 순서대로 볼 수 있습니다. 카드뉴스 1개당 이미지 생성이 2~4장 늘어나 API 요금도 그만큼 늘어납니다. 영상을 만들 때는 TOFU 문제 제기형 광고안부터 대본을 씁니다. Meta 게시 준비에는 아직 표지 이미지만 쓰며, 캐러셀(여러 장) 광고 게시는 지원하지 않습니다.

영상 제작에는 ffmpeg 8.x full 빌드가 필요합니다. 실제 모델 출력 품질과 완성 영상의 청감은 충분히 검증하지 못했으니 첫 사용은 영상 1개로 확인하세요. Flow 모드 절차는 [FLOW-MODE.md](../FLOW-MODE.md)를 참고하세요.

## 6. 검토, 중지, 재개

검토 결과 JSON과 생성 이미지는 **결과물**에서 확인합니다. ‘계속 진행’은 현재 중단 위치를 다시 실행하는 기능입니다. 저장된 외부 작업이 있으면 그 작업을 조회하는 흐름을 사용합니다.

이 베타에는 검토 보류와 승인 상태가 충분히 구분되지 않는 기존 문제가 있습니다. 화면의 완료·통과만으로 실제 사람이 승인한 것으로 판단하지 말고 이미지와 검토 결과를 직접 확인하세요. 이미지·영상 화면도 아직 같은 제작 상태를 공유할 수 있습니다.

서버나 컴퓨터를 끄면 로컬 진행 확인이 중단됩니다. 이미 공급자에 접수된 영상 생성은 계속될 수 있으므로, 무조건 초기화하여 새 요청을 보내기 전에 기존 작업 기록을 확인하세요. 초기화는 작업의 생성 상태를 변경하므로 기존 결과물을 먼저 보관하세요.

## 7. 결과물·백업·업데이트

결과물 메뉴에서 이미지, JSON 기획서, 영상 클립을 열거나 내려받습니다. 실제 파일은 기본적으로 `data/artifacts`에 있습니다.

백업하려면 서버를 종료하고 `.env`와 `data` 폴더 전체를 개인적으로 보관합니다. SQLite의 실행 중 복사는 피하고 `studio.sqlite`만 별도로 공유하지 마세요. ZIP을 다른 사람에게 보낼 때 이 폴더와 키를 빼세요.

업데이트는 서버 종료 → 개인 데이터 백업 → 새 소스 반영 → 의존성 설치 → 빌드 → 서버 시작 순서입니다. 새로운 ZIP에는 기존 `.env`와 `data`가 없으므로 필요한 경우 백업에서 본인 것만 복원합니다.

수동 실행 서버는 터미널의 Ctrl+C로 종료합니다. Windows 실행기가 시작한 서버는 실행기에 표시된 PID를 확인하고 PowerShell에서 `Stop-Process -Id <PID>`로 종료합니다.

## 8. 오류 해결

| 증상 | 확인할 내용 |
|---|---|
| 연결 거부 / 화면이 열리지 않음 | 실행기가 정상 시작했는지, 포트 4317을 다른 앱이 쓰는지 |
| Bun을 찾을 수 없음 | Bun 설치 후 새 터미널 또는 실행기 재실행 |
| ffprobe 실행 불가 | FFmpeg 설치와 PATH 또는 `.env`의 FFPROBE_PATH |
| HTTP 400 | 화면의 공급자 상세 오류. 요청 형식·지원 옵션 문제일 수 있음 |
| HTTP 401/403 | 키 전체 값, 프로젝트, API 권한, 모델 접근 권한 |
| HTTP 429 | 해당 공급자 프로젝트의 사용 한도·결제 상태 |
| 응답 형식 불일치 | 공급자 응답과 현재 코드 스키마 차이. 아래 기록으로 이슈 작성 |
| 이미지·영상 생성 후 멈춤 | 검토 JSON, 외부 작업 ID, 현재 단계 확인 |

문제 보고에는 앱 버전, OS, Bun 버전, 재현 순서, 키를 가린 오류 문구를 첨부합니다. `.env`, 전체 DB, 개인 자료는 이슈에 올리지 마세요.

## 9. 비용과 사용 범위

실제 요금은 본인의 OpenAI/Gemini 등 공급자 사용량 화면에서 확인합니다. 앱에는 정확한 청구액 집계가 없습니다. 저장된 결과물 개수만으로 실패·재시도·다른 공급자 호출을 포함한 총 비용을 계산할 수 없습니다.

공개본은 선택한 Veo 모델을 그대로 호출하며 더 비싼 모델로 자동 대체하지 않습니다. 모델을 사용할 수 없다면 상세 오류를 확인하고 명시적으로 모델을 선택해야 합니다.

로그인·다중 사용자 격리는 구현되지 않았습니다. 로컬 서버를 그대로 인터넷에 노출하는 웹 서비스 운영 방식은 지원하지 않습니다.
