# 상황에 맞는 광고 자막

대본 문장과 설득 순서는 바꾸지 않는다. 영상 기획에서 자막 연출을 정하고 합성기가 서체·위치·강조·아이콘을 재현한다. 시안 검토 단계는 생략한다는 사용자 결정에 따라 앱의 기획·저장·타임라인·최종 조립에 연결했다.

**2026-10-12 스타일 교체(사용자 결정 "앞으로는 이런 스타일로")**: 레퍼런스 쇼츠(허그만 스튜디오 세로 편집본, `data/qa/caption-ref-20261012/`)의 깔끔한 자막 체계로 바꿨다. 서체는 Pretendard Bold 하나, 말 자막은 글자에 붙는 반투명 검정 박스, 핵심 문장 2~3개만 크게 강조하고 핵심어를 팝 글자로 한 번 더 보여 준다. 완성된 MP4 는 자동 재렌더하지 않고 다음 조립부터 적용된다.

## 자막의 두 가지 모양

| 모양 | tone | 서체·크기(1080×1920) | 생김새 | 쓰는 문장 |
|---|---|---|---|---|
| 말 자막(box) | plain (옛 handwritten·warm·elegant 도 같은 모양) | Pretendard Bold 56px | 흰 글자, 글자에 딱 붙는 반투명 검정 박스(여백 14px, 불투명도 약 56%), 핵심어만 노랑 `FFE14D` | 대부분의 문장 |
| 강조 문장(emphasis) | impact | Pretendard Bold 74px | 박스 없음, 검정 외곽선 6px + 짧은 그림자, 핵심어 코랄 빨강 `FF5A4E` 1.1배, 92→100% 팝 등장 | 도입 고통 후킹·결정적 제품 사실/이유·행동 유도, 영상당 2~3개(연속 금지) |
| 팝 글자(pop) | impact 의 핵심어 | Black Han Sans 96px | 노랑 `FFD93D` 채움 + 검정 외곽선 8px + 그림자, 화면 중앙 y1000 에 70→100% 로 튀어나옴 | 강조 문장과 같은 시간, 실사 컷에서만 |

손글씨(Nanum Pen)·둥근체(Jua)·바탕체(Gowun Batang)는 기획에서 더 이상 고르지 않는다. 저장된 옛 대본이 그 값을 갖고 있으면 말 자막(box)으로 그린다. 글꼴 파일은 라이선스와 함께 그대로 번들하며 Black Han Sans 는 팝 글자에 쓴다. OS 설치 글꼴이나 원격 폰트 로딩에 의존하지 않는다.

레퍼런스에 있지만 넣지 않은 것: 컬러 이모지(libass 가 그리지 못함 — 필요하면 HyperFrames 경로로 별도 단위), 상단 헤드라인·대사 미리보기(16:9 원본을 9:16 검은 띠에 넣는 레이아웃 전용이라 세로 풀프레임 실사에는 해당 없음).

## 배치와 강조

- 실사는 얼굴 아래 가슴 부근(y1228), 설명 장면은 03 라벨 아래의 자막 안전 영역(y1584)을 사용한다. 팝 글자는 실사 컷의 화면 중앙(y1000)이다. 자동 얼굴/제품 추적을 뜻하지 않으므로 최종 가림 확인이 필요하다.
- 핵심어는 대본에서 그대로 가져온 연속 문자열 하나다. 문장 전체를 강조하지 않는다. 강조 문장은 핵심어가 필수다(팝 글자가 된다).
- 구절 전체는 짧은 페이드(말 자막) 또는 팝(강조 문장)으로 한 번에 등장한다. 글자 와이프·카피 생략·독해를 방해하는 반복 흔들기는 쓰지 않는다.
- 아이콘은 말에 직접 등장하는 물건/개념만 지원 목록에서 고른다. 잎·기름방울·캡슐·병·가게·시계·금액을 나타내는 로컬 벡터를 사용한다. 효과/인증/수익을 새로 주장하는 장식은 쓰지 않는다.
- 설명 장면은 말 자막(box)으로 읽기 우선, 아이콘·팝 글자·강한 동작을 넣지 않는다. 기존 03 라벨 폰트/스타일은 유지한다.
- 실제 글꼴의 진행폭으로 줄을 나누고 원문 전체를 보존한다. 팝 글자에 없는 글리프는 기본 글꼴로 처리하고, 안전 영역에 들어오지 않는 자막은 오류로 알려야 한다.

## 연결 범위와 검증

새 장면 기획에 captionDirection(tone, keyword, icon)을 저장한다. 별도 유료 모델 호출을 추가하지 않는다. 연출이 저장되지 않은 이전 대본은 고통(pain)·행동 유도(cta) 문장만 강조 문장이고 나머지는 말 자막이며, 저장 대본이나 승인 해시는 다시 쓰지 않는다. 저장된 완성 MP4는 자동 재렌더하지 않는다.

자동 검사(`tests/ad-caption-styles.test.ts`): 옛 tone 도 박스 모양으로 렌더, 강조 문장의 크기·외곽선·핵심어 색·팝 글자(Black Han Sans, 레이어 1), 설명 컷에는 팝 글자 없음, 팝 글자 미지원 글리프의 기본 글꼴 전환, 긴 문구 거부, 원문 불변, 무관한 아이콘 제거. 실제 영상에서의 최종 미감과 자동 기획의 강조 문장 선택 품질은 다음 제작 영상에서 확인한다(미검증).

## 구현 파일

- 모양·크기·색: shared/ad-edit-style.ts `caption.box / caption.emphasis / caption.pop`, tone → 모양 매핑과 기본 연출: shared/caption-direction.ts(`CAPTION_LOOK`, `captionDirectionFor`).
- 기획 지침: instructions/script.md의 AD_CAPTION_DIRECTION_RULES.
- 글꼴 원본·OFL 라이선스·출처·측정값: assets/fonts/captions/ (팝 글자용 Black Han Sans 포함).
- 합성: server/render/caption-ass.ts(말 자막 `CaptionBox` 스타일 BorderStyle 3, 강조 문장 `Caption`, 팝 글자 `Pop` 레이어 1), ass.ts(스타일 표), caption-fonts.ts(`captionPopFont`), caption-icons.ts. 글꼴 원본 해시와 글리프 지원 여부를 검사한다.
