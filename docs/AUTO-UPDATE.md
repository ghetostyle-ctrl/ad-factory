# 실행할 때 자동 업데이트

최신 실행기를 한 번 받은 뒤에는 `start-local.cmd` 또는 바탕화면의 **AD 스위트 실행**을 더블클릭하면 AD FACTORY의 공개 main 버전을 확인합니다. 스위트 실행 아이콘도 같은 AD FACTORY 실행기를 사용합니다. Success AI·키워드와처의 업데이트는 기존 `install-suite.cmd` 경로를 사용합니다.

GitHub 최신 커밋 SHA와 설치된 버전을 비교합니다. 같으면 바로 실행하고, 다르면 그 SHA에 고정된 ZIP을 별도 폴더에 받아 의존성을 설치하고 빌드합니다. 마지막으로 다시 제작 상태를 확인한 뒤 기존 서버를 종료하고 코드·API 설정·작업 데이터를 백업합니다. 새 코드를 적용하고 앱이 준비됐는지 확인한 후에만 설치 버전 기록을 갱신합니다.

- **작업 보호:** 실행·예약 중인 제작이나 미확인 외부 요청이 있으면 업데이트를 보류합니다. 앱이 꺼져 있어도 저장된 작업 DB를 읽기 전용으로 확인합니다. 상태를 확인할 수 없거나 다른 설치본이 포트를 사용하면 교체하지 않습니다.
- **데이터 보호:** `.env` 계열 파일과 `data`의 원본을 코드 다운로드로 덮어쓰지 않습니다. 교체 전 백업을 남기며 실패한 설치는 이전 코드·의존성·화면과 데이터로 복구합니다. 복구도 실패하면 앱을 임의로 실행하지 않고 백업 위치를 알립니다.
- **수정한 코드 보호:** 공식 저장소 main의 깨끗한 Git 설치본만 자동으로 갱신합니다. ZIP 설치본도 버전 기록 이후 코드 해시가 달라지면 덮어쓰지 않습니다. 이전 ZIP에 버전 기록이 없으면 첫 동기화 때 백업한 뒤 버전 기록을 만듭니다.
- **오프라인:** 확인·다운로드·빌드 실패 시 기존 버전으로 실행합니다. 최신이라고 표시하지 않습니다.
- **완성 결과물:** 업데이트는 이미 만든 광고를 재생성하거나 승인하지 않습니다. 서버 시작 후의 제작 재개는 해당 작업에 저장된 기존 정책을 따릅니다.

백업과 진행 기록은 설치 폴더의 `.runtime/updates/`, 현재 버전은 `.runtime/installed-release.json`, 마지막 확인 결과는 `.runtime/update-status.json`에 있습니다. 백업에는 개인 API 설정과 작업 데이터가 들어 있으므로 공유하지 마세요. 자동으로 삭제하지 않습니다. 충분한 디스크 공간이 필요하고 첫 업데이트는 다운로드·빌드·데이터 백업 때문에 몇 분 이상 걸릴 수 있습니다.

업데이트 없이 기존 버전을 실행하려면 PowerShell에서 `./start-local.ps1 -NoUpdate`를 사용합니다. 실행 중인 서버를 찾으면 그 서버를 열며, 브라우저 창만 닫아서는 서버가 종료되지 않습니다.

## 기존 사용자에게 전달할 방법

기존 실행기에는 새 기능이 없으므로 최초 한 번은 최신 ZIP을 받거나 기존 설치기를 다시 실행해야 합니다. 서버를 종료하고 `.env`와 `data`를 백업한 뒤 새 배포본으로 옮기세요. 이후부터 실행할 때마다 최신 버전을 확인합니다. 별도 EXE 설치나 Git 설치는 필요하지 않으며, Node.js 22 이상과 Bun을 사용합니다.

개발 검증은 `node --test tests/launcher-update.node.mjs`로 실행합니다. 실제 공급자 생성 API를 부르지 않는 격리 설치 테스트입니다.
